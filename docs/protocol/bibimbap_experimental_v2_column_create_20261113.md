# Experimental-only IFC4X3 Column CREATE — prospective v0.2 (Issue #118)

**Status:** narrowly implemented and verified via zero-LLM real native IFC D0; NOT full BIBIMBAP 45-case parity.
**Date:** 2026-11-13 (Asia/Seoul).
**Project boundary:** independent `bim-markup-bench` experimental source only. **BIXML/Xim product not touched.** Older v0.1 compiler, previous #112 real GPT-6 Luna outputs/scores and #116 measured capability gap matrix remain **unchanged**.

## Why a separate new version?

The actual 45-task audit (#116) classified 20 native mutation families as missing; Column-related create, delete, placement and height edits affect **at least 10 original public tasks**, but v0.1 contained **no IfcColumn native create operation** despite representing Column in its XML schema.

**This is a new prospective compiler entrypoint `src.runtime.experimental_v2_column.compile_declarative_xml_v2`**, not a rewrite of v0.1. When no Column is added, v0.2 delegates to the original pinned `compile_declarative_xml`. When exactly one new Column is present, it executes a separately allowlisted native transaction, or fails closed for unsupported mixed edits. No old result is rerun/relabelled; later real LLM experiments require newly frozen v0.2 evaluation settings and owner-approved API budget.

## Implemented native operation (ONE isolated Column)

- Input: original IFC4X3 in metres, valid frozen `sourceModelSha256`, exactly one existing zero-elevation IfcBuildingStorey, unique `Body / MODEL_VIEW` native representation context.
- LLM-visible XML is unchanged, **declarative** (no imperative opcodes):
  `<Column id="..." level="existing_storey_id" x="12" y="8" z="0" width="0.3" depth="0.3" height="3"/>`.
- The trusted compiler infers **CREATE_COLUMN** via before/after immutable XML graph state; existing IFCS GlobalIds and original unrelated entities remain untouched.
- Stable IFC GlobalId derived by original trusted binder; target class native **IfcColumn**, rectangular swept area profile, body extrusion height, native object placement, existing storey containment.
- Native IFC `IfcColumn` world's bounding-box minimum equals declared lower-left point, maximum equals `(x+width,y+depth,z+height)`. IfcOpenShell meshes are actually generated and checked, not merely metadata labels.
- Only the **single isolated added Column** is accepted. Dimensions must be positive bounded numbers. Existing IFC source is protected by its source hash, atomic staging, and full STEP preservation checks (original STEP entities can only change the actual existing containment relation; new native column and owned support entities are allowed).
- Reports operation status `COMMITTED_SCOPED_IFC4X3_COLUMN_CREATE_V2` with compiler version `experimental-column-v0.2` and `general_bim_edit_45_supported=false`. Does not incorrectly describe Column as a Wall operation.

### Explicitly NOT implemented

- Nonzero storey elevation (coordinate frame semantics ambiguous across original imported IFC sources), more than one new Column, simultaneous other edits, arbitrary diagonal/rotated or mapped profiles, Column deletion, moving or height changes, slabs/beams/door creation, full source IFC2X3/IFC4 compatibility, clash/nonintersection verification.
- v0.2 is **not yet selected by the #114 paid 25-tool runtime**; that runtime still uses v0.1 by default. A separate prospective protocol/config gate and actual offline D0 coverage are required before enabling new paid study.
- No model prompts were rewritten to include hidden benchmark target data, defaults, grader feedback, or reference solutions.
- Other original author evaluation categories and all 45 denominator results remain exactly as before.

## Deterministic real IFC D0 evidence

The original BIBIMBAP public question for `test_04` is: insert a Column of height **3m** at **(12,8)**. The task does **not** specify width or depth. Before evaluation, the test-only D0 fixture fixes both **0.3m** dimensions, x=12, y=8, z=0, and selects original ground storey. **These choices were authored in the fixture and not generated by GPT-6 Luna**.

With original `basic_tasks.ifc`, original native millimetre units normalized to metres for the compiler and converted back after the native edit, the result was:

- One new physical native `IfcColumn`; original 10 columns remain and original IFC input SHA unchanged.
- Native world-space mesh bounding box **minimum (12, 8, 0)m, maximum (12.3, 8.3, 3)m**. New IFC entity has stable native GlobalId and existing storey containment.
- Previous `IfcRoot` identities/classes preserved; all pre-existing STEP entities except an allowed original containment relationship are preserved.
- The pinned original author `execute_test()` gave **1.0** on this **developer-authored D0 IFC**, with `object_exists=1, right_location=1, right_dimensions=1, integrity_constraint=1`.
- **This author score is D0-engine capability evidence only**, NOT a new LLM benchmark result, and it must never replace the earlier GPT-6 Luna one-shot `test_04` failure.
- Full independent multi-storey/clash/semantic oracle is still unfinished.

Git-safe record `reports/bibimbap_test04_column_v2_developer_d0_20261113.json` includes original public question/source SHA, generated native result SHA, controlled dimensions and original author grading, but not original IFC corpus or hidden test implementation.
