## Strong native scope/schema checks and REAL Docker findings

The separate source-only v0.60 native oracle admits **any two distinct original Window GUIDs** removed with their two originally connected OpeningElements and exact independently computed IfcOpenShell native cleanup. It has no original answer pair, public question, grader/GT or developer control code inside the model-facing implementation. Before native commit it checks the original source SHA, candidate IFC4X3 schema, 5 remaining Windows, 5 remaining Openings, and **every surviving native STEP entity identity, attribute, geometry, root, source relation, material and reference** against a fresh independent source-derived canonical cleanup. Other original entities may not change. The source-vs-candidate incremental IFC4X3 validator must introduce **zero new schema findings**, not merely avoid gross parse errors. A low-level `ifc.remove(window)` that leaves hosted openings/relationships is rejected even if the worker otherwise returns an apparent `commit()`.

Two narrow IFC serialization differences were **observed and handled without widening edit permissions**: `IfcRelDefinesByType.RelatedObjects` and related IFC SET-valued reference aggregates may reorder, and the IfcOpenShell native `root.remove_product` API updates the shared `IfcOwnerHistory.LastModifiedDate` to the actual execution time. The independent checker normalizes **only known unordered IFC SET members** and allows at most one OwnerHistory timestamp field difference, with both timestamps and their difference within 300 seconds of trusted validation time and **all other OwnerHistory attributes unchanged**. It rejects a forged historical timestamp and unrelated Wall metadata/geometry modifications. Thus legitimate full-D, compact-D and independently executed Docker-I outputs **may differ in raw native file SHA256**, even for the same valid two-window deletion. The repeatable report stores a canonical **native semantic fingerprint SHA256** (masking only that validated cleanup timestamp and canonicalizing unordered IFC SET aggregates), **not a misleading raw file SHA**. This digest is meaningful **only after the independent source-native scope/schema oracle has passed**.

Actual evaluator-only developer cases: one source-geometry positive pair, one mixed positive/negative Window pair, one pair with two wrong Windows. For **each of the three** the independent audit generated valid native IFCs via **D_COMPLETE_XML (3), D_MANAGED_FINAL_STATE (3), genuinely OS-isolated Linux Docker I-native Python (3)**: **9/9 total actual IFC candidates passed native source-scope and schema**, **3/3 actual Docker Python worker executions attested**, **all three arms had the same canonical native semantic digest per candidate pair**, unchanged original input and zero newly introduced schema findings. Reopening outputs verifies **5 Windows and 5 linked Openings** in each. Separate true Docker adversarial tests rejected an orphaned low-level raw Window removal and a second over-deleting edit after a prior valid commit without changing the last-good IFC SHA. D-state after a valid commit followed by malformed/incomplete roster preserved its prior native IFC bytes and accepted XML.

**Important:** native source/scope validation explicitly permits wrong-but-structurally-valid window pairs, allowing downstream public-source physical correctness and independent evaluator metrics to remain separate.
